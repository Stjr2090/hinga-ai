HINGA AI ASSISTANT — BUILD AND DEPLOYMENT PLAN
Version: 0.1 planning draft
Date: 2026-08-12
Status: PLANNING ONLY — NO BUILD AUTHORIZED

======================================================================
1. MVP PURPOSE
======================================================================

Prove that a responsive web application can:

1. Remember a farmer's primary language.
2. Accept a typed farming or weather question.
3. Obtain structured weather data for the farmer's coordinates.
4. Produce a short, localized and clearly sourced advisory.
5. Optionally accept a crop image for experimental disease screening.
6. Keep every provider credential on the server.

SMS, native mobile packaging, autonomous agents and production-scale crop
diagnosis are future phases. They are not MVP deployment requirements.

======================================================================
2. PROPOSED MVP PROVIDERS
======================================================================

Translation — primary:
  Cloudflare Workers AI using Meta M2M100 1.2B.
  Reason: the hosted model supports English, Luganda and Swahili, avoids a
  dedicated model server, and fits the Cloudflare Workers AI free allocation
  for prototype-scale testing.

Translation — experimental fallback:
  Meta NLLB-200 distilled 600M, hosted in its own internal container.
  Restrictions: official checkpoint is CC BY-NC 4.0; do not use for a
  commercial launch without a licensing review. It is translation-only,
  consumes much more RAM/CPU than an API call, and may be slow on CPU.
  It must never be the only translation path during the demo.

Weather — MVP primary:
  Open-Meteo free API.
  Reason: no API key, simple coordinate forecasts and up to 10,000 calls/day
  for non-commercial evaluation.
  Restrictions: attribution is required, commercial use needs a paid plan,
  and the free service has no uptime guarantee.

Weather — production candidate/fallback:
  Azure Maps Weather.
  Decision deferred until Azure subscription pricing and regional coverage
  are verified. The weather adapter must allow changing providers without
  changing the chat API.

Crop image screening — optional MVP experiment:
  A small MobileNetV3/MobileNetV2 ONNX classifier behind an internal API.
  Initial crops should be limited to locally important classes that the
  selected model actually supports, such as maize, beans and cassava.
  PlantVillage-only accuracy must not be presented as field accuracy.
  Results must say "possible" and recommend confirmation by an agricultural
  extension worker. No pesticide instruction may rely only on image output.

Advisory model:
  Provider not yet approved. A translation model is not an advisory/chat
  model. Before implementation, select one server-side LLM that can turn
  verified weather facts and curated agronomy rules into concise language.
  The provider must be replaceable through an adapter.

======================================================================
3. TARGET ARCHITECTURE
======================================================================

Internet
   |
   v
Name.com DNS + HTTPS domain
   |
   v
HINGA frontend container (external ingress)
   |  proxies /api/* inside the Container Apps environment
   v
HINGA API/orchestrator container (internal ingress)
   |-- WeatherProvider: Open-Meteo -> future Azure Maps fallback
   |-- TranslationProvider: Cloudflare Workers AI M2M100
   |-- AdvisoryProvider: selected server-side LLM
   |-- CropModelProvider: optional internal ONNX inference container
   |-- deterministic agronomy rules and response validator
   |
   +-- Azure Key Vault / Container Apps secrets
   +-- Application Insights / OpenTelemetry

Only the frontend receives public ingress. Provider keys are never sent to
the browser. Services in one Azure Container Apps environment communicate
using internal service names.

======================================================================
4. RESPONSE PIPELINE
======================================================================

1. Validate message, selected language, coordinates and image metadata.
2. Load only the recent relevant conversation window.
3. Detect intent using deterministic routing first.
4. For weather intent, request structured weather data.
5. Convert weather values into explicit risk flags using application rules.
6. Translate incoming text only when needed.
7. Give the advisory model verified facts, risk flags and approved guidance.
8. Validate the output language, length and prohibited claims.
9. Translate the response only when the advisory model cannot reliably
   produce the selected language.
10. Return the answer plus source, timestamps and confidence metadata.

Do not ask an LLM to invent or independently retrieve real-time weather.
Do not call every provider on every request. Use timeout, fallback and
circuit-breaker policies.

======================================================================
6. COST AND LICENSING GUARDRAILS
======================================================================

1. Configure an Azure budget and alerts before deploying paid resources.
2. Keep Cloudflare Workers AI on the Free plan and enforce a backend usage
   limit below its daily allocation.
3. Treat Open-Meteo free access as non-commercial prototype infrastructure.
4. Attribute Open-Meteo weather data in the UI and documentation.
5. Treat Meta NLLB official weights as non-commercial unless relicensed.
6. Review every crop model and dataset license before downloading weights.
7. Do not trust a community model's self-reported accuracy without a local
   field-photo evaluation.
8. Do not deploy NLLB on an always-on VM for the MVP; benchmark a separate
   scale-to-zero container first.

8. MVP DECISION RECORD — 2026-08-12
======================================================================

Status: provisionally approved during planning; no build authorized.

Azure subscription:
  Azure for Students. The offer currently provides $100 Azure credit for 12
  months and does not require a credit card. HINGA will also use a project
  operating target of no more than USD $10 per month.

Azure region:
  Primary candidate: South Africa North, because it is the closest listed
  Container Apps region to the initial East African audience.
  Fallback: West Europe if the student subscription lacks regional quota or
  one of the required services is unavailable in South Africa North.
  Final selection requires a read-only subscription/quota check before build.

Azure hosting plan:
  Container Apps workload-profiles environment using only the Consumption
  profile, scale-to-zero and minimum replicas of zero during the prototype.
  Do not enable Dedicated workload profiles, GPUs, private endpoints or zone
  redundancy for the MVP because they conflict with the USD $10 target.

Domain:
  Preferred TLD: .app. HTTPS must be working before the custom domain is used.
  The string ".system" is not currently a delegated public TLD. If the user
  meant ".systems", that is a separate possible name, but .app is preferred
  for a mobile-oriented web application.
  Exact domain name and availability remain unresolved. Example only:
  hinga-assistant.app. Do not purchase a domain without explicit approval.

MVP languages:
  Approved: English (en) and Luganda (lg; Sunbird provider code lug).
  Experimental: Swahili (sw; Sunbird provider code swa), Acholi (ach) and
  Ateso (teo). Sunbird supports these languages, but HINGA will not enable
  advisory responses until agricultural phrases pass fluent-speaker review.
  Post-MVP candidates: Kinyarwanda, Somali, Runyankole, Rukiga, Lugbara,
  Luo and Kikuyu.
  Reason: provider coverage does not guarantee natural or accurate farming
  terminology. TypeScript will use stable application codes mapped to each
  provider's required language codes.

Translation:
  Deferred for the first backend pass. Cloudflare Workers AI connectivity was
  validated, but Meta M2M100 1.2B was rejected after failing English-to-Luganda
  agricultural phrase tests with repeated and unrelated output. Do not build
  the M2M100 adapter. English remains the canonical source text while a
  replacement provider is evaluated later.

NLLB:
  Excluded from the first demo. No NLLB container, weights or dependency will
  be deployed. It can be benchmarked after the prototype if still useful.

Advisory model:
  Provisional primary: Groq API with llama-3.3-70b-versatile on its free plan.
  Provisional fallback: llama-3.1-8b-instant on the same provider.
  Reason: OpenAI-compatible API, no model VM, strong free demo limits and a
  much larger free allowance than Hugging Face routed inference.
  Restrictions: free plans have no production SLA and model availability can
  change. The backend must use a provider adapter, strict token/output limits,
  timeouts and a deterministic unavailable response.
  Final approval requires creating a free Groq account and running a small
  quality test set before integration.

Hugging Face:
  Do not use Hugging Face Inference Providers as the primary demo endpoint.
  The current free-user credit is only USD $0.10 per month and is subject to
  change. Hugging Face remains useful for model discovery and model cards.

Weather:
  Open-Meteo is approved for the strictly non-commercial prototype, with
  attribution and backend caching. Azure Maps remains a future commercial or
  managed-service replacement.

Crop image screening:
  Excluded from the first demo. No crop model, image inference container or
  training dataset will be added now.

Initial agricultural scope:
  General advisory coverage for East African staples, initially prioritizing
  maize, beans, cassava, matooke/banana, sweet potato, rice, sorghum and millet.
  Disease diagnosis is out of scope for the first demo. Crop-specific advice
  must come from reviewed rule content or the advisory model with explicit
  uncertainty, never from a crop-image classifier.

Commercial status:
  Strictly non-commercial school/hackathon prototype.

Budget controls:
  [ ] Create Azure Cost Management alerts at USD $5, $8 and $10 equivalent.
  [ ] Remember that Azure budgets alert but do not automatically stop usage.
  [ ] Use scale-to-zero and minimum replicas of zero.
  [ ] Review whether GitHub Container Registry can replace Azure Container
      Registry for the prototype to preserve more of the monthly budget.
  [ ] Keep Log Analytics retention and ingestion minimal.
  [ ] Do not enable any paid model endpoint without displaying its price.
